# Chronoflux

A Pomodoro timer for Android, iOS, macOS, Windows, Linux and web. Neon-glass
interface, local-only data, no accounts.

## The design decision that matters

Most Pomodoro apps decrement a counter inside `Timer.periodic`. That is wrong on
every platform this targets: iOS and Android suspend timers in the background,
browsers throttle hidden tabs to roughly one tick per minute, desktop sleep
stops them, and `Timer.periodic` drifts regardless.

Chronoflux is **wall-clock based**. Starting an interval stores an absolute
`endsAt` instant; ticks only prompt a recompute of `endsAt - now`, and never
decrement state. A tick that is late, throttled, or missing for twenty minutes
therefore cannot desynchronise the countdown — the next observation reports the
truth. App resume triggers the same reconciliation.

Two consequences fall out of this:

- **Notifications are scheduled with the OS at `endsAt`**, not fired by the
  in-app timer, so the alert arrives even if the process is suspended. Pausing
  cancels the pending alert.
- **Catch-up replays the real timeline.** If focus and its auto-started break
  both elapsed while the app was away, both are recorded, each backdated to when
  it actually ended, and the chime is suppressed for completions discovered
  after the fact.

`lib/features/timer/application/pomodoro_engine.dart` holds this logic, behind
an injectable `Clock`/`Ticker` so the suspension cases are unit-testable without
waiting on real time.

## Layout

```
lib/
  core/          theme (palette, typography), breakpoints, formatters
  features/
    timer/       domain (cycle rule, state) · application (engine) · presentation
    settings/    durations, auto-start, alerts
    history/     7-day chart, totals, recent sessions
  data/          SharedPreferences settings · Hive session store
  services/      notifications, sound, haptics, desktop window
tool/            generate_chimes.py — synthesises the completion chimes
```

No `build_runner`: hand-written `copyWith`, manual providers, and Hive boxes of
plain maps.

## Running

```bash
flutter run -d macos     # or: chrome, or a device id from `flutter devices`
```

```bash
flutter analyze && flutter test
```

The suite covers the cycle rule, pause/resume, suspension and multi-interval
catch-up, cold-restart restore, and screen layout across five viewport sizes.

## Assets

Orbitron and Rajdhani (SIL OFL, licences in `assets/fonts/`) are bundled rather
than fetched at runtime, so the app works offline and paints immediately. The
two chimes are generated by `tool/generate_chimes.py` — regenerate with:

```bash
python3 tool/generate_chimes.py
```

## Icons

The mark is the app's own progress ring, drawn deliberately bold — thin strokes
and tick marks look right at 1024px and turn to mush at the 16px favicon.

Masters live in `assets/icon/` and are generated, not hand-drawn, so the design
is reproducible. To change it, edit the geometry constants at the top of
`tool/generate_icon.py` and run the three steps:

```bash
python3 tool/generate_icon.py      # masters, incl. macOS tile and iOS 18 variants
dart run flutter_launcher_icons    # Android / iOS / macOS / Windows / web sets
python3 tool/refine_icons.py       # fixes the gaps the tool leaves; adds Linux
```

The third step is not optional. `flutter_launcher_icons` copies the normal icon
verbatim as the web *maskable* icon, but maskable icons get cropped to a circle,
which clips the ring — the refine step swaps in a properly inset master. It also
replaces the single-resolution Windows `.ico` with a real multi-size one so
Explorer does not downscale a 256px image to 16px, enlarges the 16px favicon,
and generates the Linux set, which the tool does not handle at all.

Per-platform specifics that are handled:

- **iOS** — alpha stripped from the light icons (the App Store rejects them
  otherwise), plus the iOS 18 dark and tinted variants, which *keep* alpha
  because the system composites them over its own plate.
- **Android** — legacy mipmaps, adaptive foreground/background, and a
  monochrome layer for Android 13 themed icons. The foreground master is
  pre-inset to the adaptive safe zone, so `adaptive_icon_foreground_inset` is
  set to 0 to avoid insetting twice.
- **macOS** — a padded rounded tile per Apple's icon grid, rather than the
  full-bleed square the tool would otherwise produce.
- **Linux** — `linux/icons/hicolor/**` plus `linux/chronoflux.desktop`. A
  package should install these to `/usr/share/icons/hicolor` and
  `/usr/share/applications`; Flutter's Linux runner has no icon slot of its own.

## Platform notes

- **Android** needs core library desugaring for `flutter_local_notifications`;
  it is enabled in `android/app/build.gradle.kts`.
- **Windows and Linux** are built by the release workflow on GitHub's Windows
  and Ubuntu runners; the Linux job installs GStreamer for `audioplayers`.

## Builds, releases and downloads

GitHub Actions builds every platform from this repository:

- **Web** — [`.github/workflows/deploy-web.yml`](.github/workflows/deploy-web.yml) runs on every push to `main` (analyze → test → `flutter build web`) and publishes to GitHub Pages at `https://abhishekkulhary.github.io/chronoflux/`. One-time setup: *Settings → Pages → Source: GitHub Actions*.
- **Native apps** — [`.github/workflows/release.yml`](.github/workflows/release.yml) runs when a version tag is pushed and attaches the builds to a GitHub Release:

  ```bash
  git tag v1.0.0
  git push origin v1.0.0
  ```

  | Asset | Notes |
  | --- | --- |
  | `chronoflux-android.apk` | Signed with your release key when the `ANDROID_*` secrets are set (below); otherwise a throwaway debug key. |
  | `chronoflux-windows-x64.zip` | Includes the MSVC runtime DLLs. |
  | `chronoflux-macos.dmg` | Universal, ad-hoc signed: allow it under *System Settings → Privacy & Security* on first launch. |
  | `chronoflux-linux-x64.tar.gz` | Built on Ubuntu 24.04. |

  iOS is not distributed: installing outside the App Store needs an Apple developer account.

The web build has a **Get the app** button (hidden in the native apps) that lists these downloads from the latest release via the GitHub API ([`lib/features/get_the_app/`](lib/features/get_the_app/)).

### Android signing

Android only installs an update over an existing app when both are signed with the same key. Create one key per app, keep it outside the repository, and never commit it (`*.jks`, `*.keystore` and `key.properties` are git-ignored).

```bash
keytool -genkeypair -v -keystore ~/chronoflux-release.jks -storetype PKCS12 \
  -keyalg RSA -keysize 4096 -validity 10000 -alias chronoflux
base64 -i ~/chronoflux-release.jks | pbcopy   # macOS; Linux: base64 -w0 …
```

Add four repository secrets under *Settings → Secrets and variables → Actions*: `ANDROID_KEYSTORE_BASE64` (the base64 text), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`chronoflux`) and `ANDROID_KEY_PASSWORD` (same password for PKCS12). Set all four or none.

To sign local release builds too, create `android/key.properties` with `storeFile`, `storePassword`, `keyAlias` and `keyPassword`.
